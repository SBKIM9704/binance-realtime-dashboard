# 대시보드 지표 — 선택 근거와 임계값

> 과제 요구사항 *"해당 지표를 선택한 이유와 근거를 간단한 문서로 남겨 주세요"*에 대한 답입니다.

## 0. 관점: 왜 시세만 보여주지 않는가

이 대시보드는 시세 조회 도구가 아니라 **수집 파이프라인의 운영 화면**입니다. 그래서 지표 선택의
1원칙은 하나입니다.

> **모든 시세 숫자는 우리가 수집한 데이터에서 계산된다. 따라서 수집 품질이 곧 지표 품질이다.**

거래량이 틀렸는데 초록색으로 예쁘게 표시되는 화면은 실패입니다. 이 원칙에서 세 가지가 따라옵니다.

1. **수집 건강 지표를 시세와 동등한 1급 시민으로 취급한다** (Pipeline·System 티어).
2. **숫자마다 출처를 밝힌다** — 어떤 저장 티어에서 집계됐는지, 데이터가 얼마나 오래됐는지.
3. **판단은 색으로 끝난다** — 읽고 해석하기 전에 초록/노랑/빨강이 먼저 답한다.

지표는 운영자의 시선 흐름을 따라 **System → Pipeline → Market** 3계층으로 정의했습니다.

## 1. 화면 구성

| 화면 | 답하는 질문 | 지표 |
|------|------------|------|
| **상단 리본** (모든 화면 고정) | "지금 뭔가 잘못됐나?" | 종합 상태 · 심볼별 건강 · 지연 · Weight · 수신/초 |
| **`/` 마켓** | "지금 시장은 어떤 상태인가?" | 캔들 차트 · 종목별 시세 카드 |
| **`/ops` 운영 현황** | "수집이 정상인가?" | 핵심 4지표 · System · Pipeline · 이벤트 로그 · 캔들 데이터 |

리본을 셸에 둔 이유: 운영자의 첫 질문("정상인가")은 **클릭 없이** 답이 나와야 합니다.

## 2. Market 지표

### 2.1 왜 이 지표들인가

| 지표 | 선택 근거 |
|------|----------|
| **실시간가** | 파이프라인이 살아 있다는 가장 직접적인 증거. 틱마다 색이 번쩍여 흐름이 눈에 보임 |
| **24h 변동률** | 단일 숫자로 "오늘 시장이 어느 쪽인가"를 답하는 표준 지표 |
| **24h 고가/저가** | 현재가의 위치를 하루 범위 안에서 맥락화. 돌파·이탈 판단의 기준선 |
| **24h 거래량** | 가격 변동에 실체가 있는지 판별. 거래량 없는 급등은 신뢰할 수 없음 |
| **VWAP** | 거래량 가중 평균가. "지금 가격이 오늘 평균보다 비싼가"에 답함 |
| **변동성** | 단기 리스크 크기. 같은 1% 움직임도 변동성이 낮을 때가 더 유의미 |
| **Bid/Ask · 스프레드** | 유일한 **비(非)캔들 실시간 지표**(`@bookTicker`). 체결 비용과 시장 스트레스를 즉시 반영 |
| **최근 캔들 테이블** | 집계된 숫자의 **원본**. 대시보드가 지어낸 값이 아님을 행 단위로 검증 가능 |

### 2.2 24h 집계는 어느 데이터에서 뽑는가 — 이 문서에서 가장 중요한 부분

**문제.** 처음에는 24h 집계를 수집 인터벌(1초봉)에서 계산했습니다. 그런데 1초봉은 *운영 기록*이라
수집기가 실제로 돌아간 구간만 존재합니다. 수집기가 중단됐던 시간만큼 구멍이 뚫립니다.

실측 오차입니다 (1초봉의 24시간 밀도가 BTC 58% / ETH 54%였을 때, Binance 공표치 대비):

| 지표 | 1초봉 기준 | **조밀 티어 기준** |
|------|-----------|------------------|
| BTC 24h 거래량 | **−35.1%** | **−0.03%** |
| ETH 24h 거래량 | **−59.7%** | **−0.01%** |
| ETH 24h 저가 | +1.9% (저점을 통째로 놓침) | **0.00%** |
| VWAP | −0.8% | **−0.00%** |

**해결.** 24h 집계는 **그 구간을 덮으면서 충분히 조밀한, 가장 정밀한 티어**에서 계산합니다
(`pick24hSource`). 1초봉은 원래 목적인 수집 품질 감시에만 씁니다.

이 판단이 실무적으로 가장 중요한 부분입니다 — **"정밀한 데이터"와 "완결된 데이터"는 다르고,
집계에 필요한 건 후자**입니다.

### 2.3 표시 단위를 왜 바꿨는가

두 지표는 계산은 맞는데 **표시 때문에 죽어 있었습니다.**

**변동성 → 백분율이 아니라 bp(베이시스 포인트).**
원값은 로그수익률 표준편차로 약 `4e-5`입니다. `(v*100).toFixed(2)`로 찍으면 **항상 `0.00%`**가
나옵니다. 읽는 사람에게 이건 "작은 값"이 아니라 "미구현"으로 읽힙니다. bp로 바꾸면 `3.05 bp`처럼
비교 가능한 숫자가 됩니다. 라벨에 창(window)도 명시했습니다 — 24h 지표들 사이에 놓이면 독자가
24시간 변동성으로 오해하기 때문입니다.

**스프레드 → 퍼센트가 아니라 틱(tick).**
BTCUSDT·ETHUSDT는 최고 유동성 페어라 스프레드가 **거의 항상 정확히 1틱(0.01 USDT)**, 즉 물리적
최소값입니다. 퍼센트로 찍으면 영원히 `0.000%`/`0.001%`이고 정보가 없습니다.

스프레드는 **평상시 값이 아니라 벌어질 때** 의미가 생기는 지표입니다. 틱으로 표기하면 `1틱`은
"정상"으로 읽히고 `3틱`은 즉시 눈에 띕니다. 퍼센트는 참고로 병기합니다.

> 틱 크기는 Binance `exchangeInfo`의 `PRICE_FILTER` 값이며 `src/lib/market-meta.ts`에 상수로
> 둡니다. 심볼을 추가하면 여기에 등록해야 합니다.

## 3. Pipeline 지표 — 수집이 정상인가

| 지표 | 선택 근거 | 🟢 | 🟡 | 🔴 |
|------|----------|----|----|----|
| **WS 연결** | 수집의 생사. 끊기면 나머지는 전부 과거 데이터 | 연결 | — | 끊김 |
| **Msg/s** | **연결됐지만 조용한 상태**를 잡는 지표. WS는 살아 있는데 데이터가 안 오는 장애가 실재함 | > 0 | — | 0 |
| **지연(Lag)** | 마지막 캔들이 얼마나 뒤처졌나. 실시간성의 직접 측정 | < 5초 | 5–30초 | > 30초 |
| **복구율** | 탐지한 결측 중 실제로 채운 비율. **데이터 완결성의 핵심 지표** | 100% | 95–99% | < 95% |
| **탐지 / 복구 수** | 복구율의 분모·분자. 비율만 보면 "1건 중 1건 = 100%"를 구분 못 함 | — | — | — |
| **재연결 횟수** | 네트워크 불안정의 누적 신호 | — | — | — |
| **에러/분** | 최근 1분 에러 발생률 | 0 | 1–5 | > 5 |
| **총 레코드** | 전 티어 누적 저장량 (실시간 인터벌 수치 병기) | — | — | — |
| **이벤트 로그** | 위 숫자들의 **시간축 서사**. "왜 복구율이 떨어졌나"는 로그에만 있음 | — | — | — |

**임계값 근거.** 지연 5초는 1초봉 5개 분량으로, 일시적 지터와 실제 장애를 가르는 선입니다.
복구율은 100%가 아니면 이미 데이터에 구멍이 남아 있다는 뜻이라 95% 미만을 위험으로 둡니다.

임계값은 화면의 값 옆에 그대로 인쇄합니다(`0.8s` `< 5s`). **문서에만 있는 색상 계약은 화면에서
검증할 수 없기 때문입니다.**

## 4. System 지표 — 수집기 프로세스와 API 예산

| 지표 | 선택 근거 | 🟢 | 🟡 | 🔴 |
|------|----------|----|----|----|
| **CPU · RAM · 업타임** | 상주 프로세스의 기본 건강. 업타임은 크래시 루프를 드러냄 | — | — | — |
| **REST 호출/분** | 백필·정합이 REST를 얼마나 쓰는지 | — | — | — |
| **REST Weight** | **Binance는 요청 수가 아니라 weight로 제한**(6000/분). 초과 시 IP 차단 | < 70% | 70–90% | > 90% |
| **재시도 / 429 / 5xx** | 429는 이미 한도를 건드렸다는 신호, 5xx는 거래소 측 장애 | 0 | 발생 | — |

Weight를 넣은 이유: 대량 백필은 **조용히 한도에 접근하다 한순간에 차단**됩니다. 차단된 뒤
알아채면 이미 데이터가 비어 있습니다.

## 5. 신뢰성 장치 — 화면이 거짓말하지 않게

지표 자체만큼 중요한 것이, **지표를 못 믿을 상태일 때 그걸 드러내는 것**입니다.

| 장치 | 이유 |
|------|------|
| **낡은 프레임 감지** | SSE가 끊기면 마지막 값이 그대로 남습니다. 3초가 지나면 종합 상태를 **위험**으로 강제하고, `연결 끊김 · 마지막 수신 N초 전`을 띄우며, 모든 수치를 흐리게 합니다. **거짓 초록은 깨진 화면보다 나쁩니다** |
| **호가 신선도** | Bid/Ask 옆에 경과 시간을 표시하고 5초를 넘기면 빨강 처리 |
| **집계 출처 표시** | 차트와 카드가 어느 저장 티어에서 나왔는지 명시 |
| **빈 구간 안내** | 데이터 없는 구간은 빈 캔버스가 아니라 "저장된 캔들이 없습니다 · N부터 데이터가 있습니다" |
| **색 단독 인코딩 금지** | 임계 색상에는 항상 수치·라벨이, 캔들 등락에는 ▲▼와 OHLC 수치가 동반됩니다 (적녹색약 대비) |

## 6. 표시 방식 선택

| 방식 | 쓴 곳 | 이유 |
|------|------|------|
| **캔들 차트** | 가격·거래량 | 결측 구간이 **빈 봉으로 드러남**. 선 그래프는 구멍을 이어버려 수집 문제를 감춤 |
| **숫자 카드** | 시세 · System · Pipeline | 단일 값의 즉시 판독. 색상 코딩과 결합 |
| **스파크라인** | 종목 카드 | 축 없이 최근 추세만. 카드 안에서 방향만 전달 |
| **테이블** | 최근 캔들 · 이벤트 로그 | 시간순 원본 데이터 검증 |
| **리본** | 종합 상태 | 항상 보이는 한 줄 요약 |

**등락 색은 언어를 따릅니다** — 한국어 UI는 국내 거래소 관례대로 상승 빨강 / 하락 파랑, 영어
UI는 초록 / 빨강입니다. 관례를 뒤집으면 독자가 시장을 거꾸로 읽습니다
(`src/lib/trend.ts`에 단일 정의).

## 7. 의도적으로 넣지 않은 것

| 항목 | 이유 |
|------|------|
| **호가창 깊이(depth)** | `@bookTicker`는 최우선 호가만 제공. 깊이는 별도 스트림이 필요하고 저장량이 급증 |
| **기술적 지표(MA·RSI 등)** | 이 대시보드는 **투자 판단 도구가 아니라 운영 도구**. 파생 지표는 수집 품질을 가림 |
| **알림·경보** | 임계값 색상까지가 이번 범위. 알림은 전달 채널·중복 억제·에스컬레이션이 따라붙는 별도 설계 |
| **일/주/월 캔들 뷰** | 기본 보존이 7일이고 일봉 경계가 UTC 자정이라 국내 거래소 일봉과 하루가 어긋나 보임 |
